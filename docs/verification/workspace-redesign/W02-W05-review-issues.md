### WR-R01：保存期间继续编辑会丢失新内容

位置：[App.tsx](../../../apps/web/src/App.tsx)，`ManuscriptPanel.save`（第 1809 行）及编辑框（第 1916 行附近，以函数定位为准）。

复现步骤：

1. 在已加载的 `main.tex` 中追加 `% first submitted edit`，点击“保存新版本”。
2. 让请求正常到达宿主并保存，但延迟把成功响应交给浏览器。
3. 此时编辑框仍可输入，将内容继续改为含 `% NEWER_UNSAVED_EDIT` 的新草稿。
4. 释放先前保存响应，新草稿消失，编辑器退回第 1 步提交的内容，没有确认提示。

本次观察：`editableWhileSaving=true; newerEditKept=false; displayedSavedVersion=true`。

原因：保存开始时捕获旧正文；成功后无条件删除 `fileDrafts[file]`，没有判断草稿是否在请求期间继续变化。

修复及关闭条件：使用草稿修订号/提交快照比较，保存成功仅清除该次提交的草稿；若存在后续编辑，保留新正文并正确更新基线。也可明确禁止保存期间编辑，但必须保证任务/文件切换不误清理其他草稿。加入延迟成功/失败、连续编辑、切换任务/文件的真实 HTTP 浏览器回归，确认新草稿与服务端版本均正确后复验 WT06/WT13。

### WR-R02：可见选区与原文坐标不一致

位置：[App.tsx](../../../apps/web/src/App.tsx) 第 637 行的 `ReferenceText`；[materials.ts](../../../apps/server/src/materials.ts) 的 `truncateNote`；[references.ts](../../../apps/server/src/references.ts) 第 31 行和选区校验。

复现步骤：

1. 导入文本 `First line.\n\nSecond line with   spaces.\n`。
2. 打开材料“笔记与来源”，可引用文本显示为 `First line. Second line with spaces.`。
3. 全选该文本，点击“引用所选文本”。
4. 宿主返回 HTTP 400 / `INVALID_REFERENCE`：`选区与来源不匹配，无法可靠定位`，该可见文本无法按所示选区引用。

原因：导入摘要压缩了空白并可能截断；前端使用摘要的 start/end/quote，宿主却对 `text/plain` 原文件内容进行精确切片校验。换行、多空格和截断都可能使坐标不一致。宿主拒绝是正确的保护行为，不能删除校验来“修复”。

修复及关闭条件：引用控件读取与宿主一致的、带版本的规范原文；或明确区分摘要与原文定位并实现可验证映射。覆盖 LF/CRLF、空行、制表符、多空格、中文和超过摘要长度的文件，验证前端选区、宿主快照及模型输入的文本和定位完全一致，再复验 WT09/WT13。

### WR-R03：确认响应丢失后重发导致二次调用

位置：[App.tsx](../../../apps/web/src/App.tsx) 第 504–527 行，`sendMessage` 每次点击生成 `msg_${crypto.randomUUID()}`，失败后恢复正文及引用但没有保留本次 clientId。

复现步骤：

1. 输入 `Retry after lost acknowledgement` 并发送。
2. 将该请求真实转发到宿主，确认它已接收并调用受控 Agent，再中断返回浏览器的响应。
3. 浏览器报错并恢复输入。用户按同一条失败消息重发。
4. 宿主再次接受；同样的正文产生两次调用、两个不同 clientId。服务端对相同 ID 的幂等保护因此无法生效。

本次观察：`calls=2; differentClientIds=2`，不是未到达宿主的请求，也没有修改服务端幂等逻辑。

修复及关闭条件：为一次逻辑提交保存稳定 clientId 和精确正文/引用快照；提交结果不确定时查询状态或以原 ID 重试。只有用户明确发起新消息/更改提交内容时才创建新 ID。覆盖“已接收但响应丢失”、请求未到达、SSE 先到、切换任务、刷新恢复、有引用消息等场景，断言一次逻辑提交仅一次模型调用及一份持久来源，再复验 WT10/WT13。
