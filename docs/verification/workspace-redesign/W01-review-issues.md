### W01-R01：切换任务时可能发错会话

位置：[App.tsx](../../../apps/web/src/App.tsx)，`loadTask`（被验收提交第 232–242 行）及 `sendMessage`（第 394–408 行）。

复现步骤：

1. 在 1440×900 浏览器中打开任务 A，输入一条草稿。
2. 延迟任务 B 的详情请求，点击 B，保持请求未返回。
3. 此时左侧已选中 B，右侧标题和内容仍属于 A，发送按钮仍可点击。
4. 点击发送，宿主收到的任务 ID 属于 B。

实际观察：`selectedTaskB=Task B; displayedTask=Task A; sendEnabled=true; postedTo=Task B`。

原因：切换开始就更新 `taskId`，但旧 `detail/events/liveText` 保留到新详情返回；发送及模型切换没有校验已加载详情与目标任务一致。

修复要求：加载期间禁止发送、停止及模型修改等依赖任务的操作，或原子切换完整任务状态；请求失败时也不得留下显示与目标不一致的可操作界面。

关闭条件：增加延迟/失败详情请求下的 A→B→A 及跨项目用例，断言屏幕归属、发送目标、停止目标与模型修改目标始终一致，无写错任务；浏览器回归通过后复验 WT03。

### W01-R02：迟到响应覆盖模型选择

位置：[App.tsx](../../../apps/web/src/App.tsx)，SSE 触发详情刷新后的 `if (current()) setDetail(fresh)`（被验收提交第 283 行）。

复现步骤：

1. 同一任务先切到 `deepseek-v4-pro`。
2. 捕获此次 `model_changed` 触发的详情响应，内容为 Pro，但暂不交给前端。
3. 再切到 `deepseek-flash`，确认宿主与界面均为 Flash。
4. 释放第 2 步的旧响应，界面被覆盖回 Pro，宿主仍为 Flash。

实际观察：`serverModel=deepseek-flash; displayedModel=deepseek:deepseek-v4-pro`。

原因：详情刷新只校验当前任务 ID，没有比较请求序号或模型版本；同一任务的较早响应仍可覆盖最新确认结果。

修复要求：对详情刷新及模型切换响应使用统一的顺序/版本校验，丢弃过期结果；不能仅依靠任务 ID 匹配。

关闭条件：增加受控乱序响应的连续切换测试，并覆盖 A→B→A 后旧响应到达；界面、持久任务选择和下一条实际调用模型一致后复验 WT16。

### W01-R03：窄屏模型入口不可达

位置：[styles.css](../../../apps/web/src/styles.css)，`@media (max-width: 900px)` 下 `.chat-panel { display: none; }`（被验收提交第 323–325 行）。

复现步骤：打开已有任务，将浏览器视口设为 390×844，检查会话、消息输入框和模型选择控件。

实际观察：`chatVisible=false; modelSelectVisible=false; messageInputVisible=false`，没有可恢复的会话入口。

修复要求：提供工作区/会话的显式切换和可达入口，保留任务归属及草稿；WT16 已要求窄屏与键盘可选择模型，不能以完整移动布局归 W02 为由标整项通过。

关闭条件：在 390px 下通过键盘/触控展开会话、选择模型、返回工作区，确认状态保留、输入和主要操作可用；补充浏览器用例并复验 WT16。
