# ScholarFlow Agent 能力与工作区反馈架构

更新：2026-10-22。状态：框架已确认，待实施；本次仅更新文档与相关测试，不实现业务功能。来源：用户确认本轮关于文献获取、全工作区反馈及 Pi 动态装配的讨论；各工作区工具细节后续讨论。

与 [当前产品共识](WORKSPACE_PRODUCT_DISCUSSION.md)、[前端需求](FRONTEND_PRODUCT_REQUIREMENTS.md) 配套；实施分批及测试追踪见 [PLAN 第 9 节](../PLAN.md#9-agent-能力与产物反馈后续计划)。本文定义边界，不把暂定工具名、参数或供应商当成已定接口。

## 1. 确定的架构

| 决定 | 约束 |
| --- | --- |
| 每个任务一个主 Agent 会话 | 延续 Pi session；切换工作区不换 Agent，同项目按来源共享资料，不注入全部聊天 |
| 小型基础能力＋按需装配 | 初始只暴露必要基础工具与简短能力目录；领域工具注册后可保持未激活 |
| 主 Agent 决定需求，宿主决定可用范围 | 根据用户目标、任务及当前对象请求能力；宿主校验依赖、配置、项目归属、权限及预算 |
| 能力不绑定页面 | 阅读时可安排实验或改稿；页面仅提供当前对象提示，不强制分类或自动放开能力 |
| 真实数据驱动工作区 | 工具调用领域服务，服务保存记录和文件，再通知前端；聊天文本不是产物数据库 |
| 先保持单主 Agent | 不建立固定多 Agent 团队，不默认每轮运行额外的意图分类模型 |

大量并行阅读等确有需要时，再评估独立执行上下文、隔离工具范围和有来源的有界结果回传；它不是本轮实施前置，也不是 Pi 自动内置的子 Agent。下载、训练和编译 worker 是后台作业，不是额外的推理 Agent。

## 2. Skill、Tool、MCP 和知识库的职责

| 部分 | 负责什么 | 不应承担什么 |
| --- | --- | --- |
| Skill | 调研、比较、阅读、写作等方法和步骤；按需读取正文，保留来源/版本 | 不授予执行权限，不把下载文件中的文字升级为系统指令 |
| Tool | 有明确参数、结果、错误和归属的可验证动作，调用领域服务 | 不向模型倾倒外部服务的全部底层接口 |
| MCP / 外部 API | 连接外部检索、全文或其他服务；由宿主适配为稳定的领域能力 | 连接成功不等于一定能检索、下载或解析论文 |
| 知识库 | 文献身份、附件版本、原文、页码/位置、笔记、集合、引用与证据 | 不把聊天摘要或向量索引当作唯一事实来源 |
| 领域服务与作业 | 下载、解析、入库、实验、构建、版本和状态管理 | 不依赖主 Agent 持续生成文本来维持长作业 |

先采用 SQLite＋文件存储，按需补全文检索；向量检索、复杂知识图谱以后按需求评估。当前聊天配置的 MCP 不自动成为 ScholarFlow 的运行能力，必须在产品宿主中接入并验证。

## 3. 动态装配流程

1. 宿主注册工具实现和能力映射。能力目录只提供简短用途、可用状态；工具完整参数和 Skill 正文按需提供。
2. 任务开始时激活少量基础工具，保留能力发现/加载及恢复任务所需入口。具体核心清单后续确定。
3. 主 Agent 根据请求和任务状态选择能力；加载入口可暂称 `load_capability`，此名称及参数尚未定稿。
4. 宿主检查能力存在、依赖/凭据、项目归属和权限；失败返回原因，不能报告“已加载”。Skill 读取和工具激活分别处理，并可由同一加载入口协调。
5. 更新该任务的活动工具集合，在下一次模型请求携带新的工具定义；可在同一条用户消息处理中继续执行，无需用户另发“继续”。
6. 任务阶段变化后可调整活动集合；策略后定，避免无限累加。保留必要查询/取消入口，在模型请求之间协调更新，不能让加载与切换并发污染其他任务。

Pi 1.3.0 已核对的接口为 `pi.registerTool()`、`defaultActive: false`、`pi.getActiveTools()`、`pi.setActiveTools()`；宿主 session 也有 `setActiveToolsByName()`。对普通直接调用工具使用 `exposure: "direct"`，注册与启用分开。

`setActiveTools()` 替换整个活动集合，添加能力时应保留必要核心工具；未知名称会被忽略，因此宿主须验证实际结果。SDK 的初始工具配置也必须允许目标工具进入注册表，不能先将其过滤掉，再期待启用成功。`hidden` 不能作为日后正常激活的默认状态。

未激活主要表示不向模型直接声明，**不等于权限隔离**；其他暴露/执行方式仍须单独控制。激活不执行工具、不提升权限，也不自动加载 Skill。停用不会擦除历史工具结果或已读 Skill；重开任务与切换模型时按当前环境重新校验能力，历史“曾加载”不代表现在可执行。

核对依据：项目锁定的 `@earendil-works/pi-coding-agent` 1.3.0 安装包中的 `docs/extensions.md` 和 `dist/core/extensions/types.d.ts`；上游说明见 [动态激活工具](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md#activate-tools-dynamically)。Pi 提供机制；能力目录、映射、加载策略和预算由 ScholarFlow 实现。

## 4. 上下文控制

- 常驻：当前任务目标、约束、已确认方案摘要、当前对象引用、必要状态及简短能力目录。
- 按需：相关 Skill、论文片段、指定运行指标/日志和稿件片段；正文、长日志及大表保存后台，以对象/版本/位置查询。
- 限量：检索分页，读取分段，工具返回有界摘要与可继续读取的引用；不能以静默截断的笔记冒充完整原文。
- 预算：按实际模型窗口预留输出空间，对基础提示、活动工具、Skill、历史、引用及工具结果共同计量；字符长度估算只作预警，不当精确 token 数。数值上限通过实测再定。
- 恢复：复用 Pi 压缩；压缩前后均可从持久记录恢复已确认条件、来源和运行，不因历史缩短重复启动实验。加载/卸载改变工具定义，历史仍占上下文，也可能影响缓存。

评估记录模型/配置、输入量、活动工具数、读取量、压缩次数、延迟、可得的使用量/费用及证据正确性。无实测前不宣称上下文已经失控，也不保证动态装配能消除所有增长。

## 5. 所有工作区共用的反馈规则

领域服务先保存实际记录/文件及版本，再产生变化事件；前端根据对象标识读取最新状态。共通关联至少涵盖项目、来源任务、对象、版本及作业状态；具体字段和事件名待实施设计。

| 场景 | 自动反馈 | 真实性与版本要求 |
| --- | --- | --- |
| 文献 | 获取/解析进度、入库记录、附件和阅读入口更新列表 | 元数据、已下载、可读、解析失败分开；保留来源和论文/附件版本 |
| 实验与结果 | 运行状态、已收集的指标、表格/图表和原始产物出现在对应工作区 | 按约定产物格式导入，缺失/错误明确反馈；退出成功不等于科研达标，指标绑定 runId 和原始文件 |
| 写作排版 | Agent 修改实际稿件文件，保存后触发或合并编译，预览对应源码版本 | 不是仅在聊天输出代码；遵守草稿/正式稿件确认，旧编译不得覆盖新预览 |
| 方案与审稿 | 方案版本、确认状态、意见与修订关联更新 | 保留用户确认和修改来源，不能因更新界面跳过审批 |

作业状态与 Agent 回答状态分开。断线后可查询快照、重连或补齐变化；重复通知不重复入库/执行；其他任务的更新不覆盖当前对象。用户当前查看的对象按版本更新，其他产物提供入口，不自动抢焦点或覆盖未保存编辑。

编译失败保留上次成功 PDF，并明确“旧版本”；自动预览是保存和构建链路的反馈，不承诺每次按键都同步编译。

## 6. 文献工作区的首要方向

覆盖两类目标：指定论文的定位/公开全文获取，以及按主题和明确时间范围收集、筛选、归类和形成有证据的方向概览。“时间序列近两年”仅是例子，实际时间区间、来源覆盖和筛选条件需记录。

优先闭环：输入 DOI/arXiv 标识、链接或用户文件 → 识别论文 → 查找允许获取的公开版本 → 后台下载 → 校验 PDF 内容及论文身份/版本 → 保存原文件、完整文本与位置、来源/时间/许可/校验信息 → 自动入库并更新列表。不能仅凭 `.pdf` 后缀或响应类型把登录页当论文；身份不确定时保留待核验状态。

同一论文复用文献身份记录，预印本/出版版等作为不同附件或版本；重试不重复建档。无公开副本、网络失败、需授权、解析失败分别反馈，可重试或由用户导入合法已有副本。检索和公开全文解析分工，Crossref 元数据不能当作已经获得原文；不以自动网页抓取 Google Scholar/WoS 作为唯一获取路径，不承诺免代理或覆盖所有付费全文。

方向概览保存检索条件/时间、集合、纳入依据和证据；区分只读元数据/摘要与已读全文，不凭单一结果集宣称全领域热点。工具可覆盖检索、集合整理、获取、阅读、库内检索和产物保存，但具体数量、命名、参数、供应商与 Skill 拆分均待文献专题设计，不以本段一次定完。

## 7. 当前实现差距

2026-10-22 只读代码核对，不代表新功能完成：

| 当前事实 | 后续补齐 |
| --- | --- |
| [Agent](../apps/server/src/agent.ts) 按任务保存会话，18 个研究工具与 4 个只读内置工具一起启用 | 小型基础集合、能力目录/加载入口、按任务活动集合与恢复 |
| [load_skill](../apps/server/src/agent-tools.ts) 读取 Skill 正文并记录来源 | 与能力激活协调，不能假设现有读取自动切换工具 |
| [上下文](../apps/server/src/context.ts) 汇集项目材料、运行与当前结果 | 相关性选择、分页/分段及共同输入预算；避免项目资料随规模全量增长 |
| [材料导入](../apps/server/src/materials.ts) 的 DOI 路径保存元数据，URL/PDF 可下载提取截断笔记 | 公开全文解析、文件/身份校验、独立全文证据存储及获取作业状态 |
| 已有材料事件、运行/稿件记录及视图刷新 | 对所有视图统一持久记录反馈、重连补齐及版本一致性；不另造聊天产物副本 |
