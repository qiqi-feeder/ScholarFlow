## 1. 产品定位与范围

ScholarFlow 是单用户、本地优先的科研 Agent 工作台。用户围绕一个研究项目，与 Agent 持续协作，组织文献和方案，进行受控实验，分析真实结果，撰写、编译和导出 LaTeX 稿件，并可接续处理审稿意见。

首版重点是让用户始终能回答三个问题：**正在研究什么、Agent 正在做什么、当前产物和依据在哪里。**

### 1.1 本次前端设计必须承载

- 项目和任务管理，以及每个任务独立的持续对话。
- 在对话框内查看并切换当前任务使用的模型。
- 论文/材料查找、导入、阅读、来源查看和显式上下文引用。
- 研究方案编辑、确认、复现材料准入及待确认操作。
- 实验提案、审批、运行状态、日志、取消及结果核验。
- 指标、条件、图表和原始产物的关联与比较。
- 稿件、参考文献、图表、版本、PDF 编译预览和投稿包导出。
- 审稿意见与修订/补实验的衔接。
- 模型凭据、检索、实验环境、构建环境和 Skill 依赖状态的设置入口。
- 工作现场恢复、未保存编辑保护，以及所有工作视图下的后台状态提示。

### 1.2 首版范围之外

多人协作与账户体系、远程集群管理、自动投稿、Word/富文本编辑、通用 PDF 批注/OCR、完整双语阅读器、Skill 市场、节点式 Agent 编排、跨设备工作区同步、复杂仪表盘均不作为本次原型必须项。可为未来留空间，不设计成已经可用的按钮或承诺。

本文所有页面和状态均为目标需求，不代表现有代码已实现。实验成功退出、指标核验、论文复现达标是不同结论，界面必须分别表达。

## 2. 目标用户

| 用户 | 常见起点 | 主要目标 | 设计需要照顾 |
| --- | --- | --- | --- |
| 研究生与独立研究者 | 研究问题、论文或模型名称 | 梳理文献、形成方案、完成实验和论文 | 上手路径清楚；下一步可操作；能随时询问依据 |
| 已有研究资产的研究者 | 代码、数据、运行结果或已有稿件 | 接续分析、补实验、写作或修订 | 可以从中途进入，不强制重新走完整流程 |
| AI/计算机/数据科学方向的实验使用者 | 官方脚本、参数与目标数据 | 复现基线、检验一次受控修改 | 条件、资源预算、运行状态和原始结果清晰可查 |

这些是使用场景画像，不是三种账户角色或权限等级。首版仍是同一个本地用户，用户负责关键研究决策和实验批准。

## 3. 核心使用场景

| 场景 | 用户目标 | 涉及页面/视图 | 主要操作与产物 |
| --- | --- | --- | --- |
| SC01 | 从研究问题或论文开始调研 | P01、P02、P03、P04 | 创建项目/任务，检索和导入材料，阅读并向 Agent 提问，保留来源和笔记 |
| SC02 | 形成并确认可执行的研究方案 | P02、P03、P05 | 明确目标、假设、指标、条件、预算；检查准入证据，确认或退回方案 |
| SC03 | 执行基线和一次受控修改 | P05、P06 | 查看精确实验提案，批准/拒绝，跟踪运行和日志；有需要时取消实验 |
| SC04 | 理解结果及其可信边界 | P06、P07 | 导入指标、核验产物、比较条件、阅读图表，形成带来源的分析结果 |
| SC05 | 根据已核验结果写作和交付 | P03、P07、P08 | 编辑稿件/引用，检查修改，编译 PDF，处理错误，导出投稿包 |
| SC06 | 接续已有论文或审稿意见 | P02、P08、P09 | 打开已有材料，导入意见，逐条讨论与修订，必要时创建补实验任务 |

允许从任意场景进入。任务表示一个研究目标，工作方式只决定如何显示内容；阅读、分析、写作之间切换不自动创建新任务。

## 4. 全局工作台结构

### 4.1 左侧：项目与任务导航

- 项目切换、新建项目、项目基本信息入口。
- 当前项目/任务的紧凑选择入口，展开任务列表时显示标题、最近活动、运行中/待确认/错误等摘要；专注阅读收起内容列表时也可切任务。
- 新建任务入口，可填写目标，必要时附已有材料或审稿意见。
- 可折叠为窄导航；折叠后仍能辨认当前项目/任务并展开。
- 设置和环境状态入口。最左图标切工作视图，下方内容列表随视图显示论文库、方案证据、实验运行、分析对象、稿件目录或审稿意见；完整任务列表按需展开，不重复常驻“阶段列表＋工程产物文件”。项目文件保留可展开入口，不另外叠加永久大侧栏。

### 4.2 中央：任务工作区

- 项目/任务名称和当前工作内容；必要时显示保存、构建或核验状态。
- 以具体对象打开标签，例如“论文 A”“基线运行”“结果对比”“main.tex”。
- 单内容、双内容对照、列表＋详情三种基本结构；材料列表、引用、日志等辅助区可展开/收起。
- 同一对象重复打开时定位已有标签，用户可保留重要内容；关闭正在查看的内容不删除真实文件。
- 阅读、实验、分析、写作四种默认工作方式；方案和审稿复用编辑/对照能力，不另造固定流水线。

### 4.3 右侧：常驻任务会话

这是全局模块 G01，不是只在“任务页面”才能看到的一张独立页面。

| 模块 | 功能需求 | 原型应表达 |
| --- | --- | --- |
| 会话头部 | 当前任务标题、状态、当前生效模型 | 明确正在和哪个任务交流、实际使用哪个模型，切任务不会误发到旧会话 |
| 模型选择 | 在对话框内切换当前任务模型，无需进入设置页 | 展示模型及提供方、可用状态；沿用原稿输入区入口，按 MS01–MS07 实现状态 |
| 消息区 | 用户消息、流式回答、引用、错误与历史记录 | 长内容可阅读，工具详情按需展开，用户向上阅读时不强制滚到底 |
| 上下文引用区 | 本条消息选中的论文、段落、运行、图表或稿件，可移除和打开来源 | 打开文件与引用文件有区别；发送前知道 Agent 会参考哪些内容 |
| 执行与确认 | 简洁执行进度，查看方案/提案/产物的入口，确认/拒绝操作 | 重要决策对应明确对象与版本；详细配置可在中央查看 |
| 输入区 | 多行输入、发送、引用添加、未发送草稿 | 中文输入法不误发送；发送中防重复；网络失败保留输入和引用 |
| 停止回答 | 停止当前模型回答 | 按钮明确标为“停止回答”，不能冒充“取消实验” |
| 产物入口 | 从回答打开论文、结果或稿件 | 有可访问的真实产物才显示可打开入口，不仅展示成功卡片 |

桌面中，切换中央内容后会话仍在右侧。用户主动收起时保留展开入口；页面或 Agent 不得自动隐藏。无任务时显示“选择或新建任务”，不允许发送到不存在的会话。

#### 4.3.1 对话框内的模型切换

用户于 2026-10-22 明确补充“模型切换”。这是 G01 的必备功能；下表为实现与验收要求，Pi 实际兼容能力在 W00 核对，不代表当前已实现，也不等待继续生成原型。

| 编号 | 功能需求 | 交互与边界 |
| --- | --- | --- |
| MS01 | 对话框内直接选择模型 | 显示当前生效模型和提供方；列表来自宿主实际支持的选项，不写死所有厂商均可用；未配置项说明原因并链接 P10 |
| MS02 | 当前任务选择与默认值分开 | P10 管理凭据和新任务默认模型；对话框只改当前任务。选择按任务持久化，切任务/刷新/重启后恢复；修改默认值不覆盖已有任务的明确选择。旧任务无选择时的默认值继承规则在 W00 明确 |
| MS03 | 从下一条消息生效 | 不创建新任务、不清空历史、草稿、引用或中央工作现场，不自动重发旧问题；历史回答保留实际提供方/模型标识，不随当前选择改写 |
| MS04 | 回答期间禁用切换 | 流式回答、工具执行或停止回答尚未完成时禁用选择，并说明需等待本轮结束或先停止回答；停止完成后才可切换。独立实验继续运行，切模型不取消或重跑实验 |
| MS05 | 服务端确认后显示已生效 | 切换处理中保留原生效模型并防止新消息发送，确认成功后才更新；失败保留原模型和草稿并可重试。发送与切换由服务端保证顺序，过期任务响应不能改写当前选择；重复请求不能产生模型调用 |
| MS06 | 不可用和能力不兼容有解释 | 无凭据、认证失败、限流、模型下线或不支持所需工具/上下文时，明确原因和处理入口；无法续接现有历史/引用时阻止继续并解释，不静默删历史、丢引用或降级到其他模型；不虚构费用或能力 |
| MS07 | 保持科研权限及凭据边界 | 更换模型不改变方案确认、实验批准、预算、工具权限或写稿权限；模型列表与切换接口只返回模型标识和安全状态，不回传已保存的完整 Key；设置页输入的凭据不写入浏览器持久化缓存 |

空列表提供“配置模型”入口；列表加载、切换中、切换失败与调用失败分别反馈。手机“对话”视图也能打开选择器并看到当前生效模型，操作不依赖悬停。模型入口沿用原稿输入区，列表密度与提供方分组按实际可用项在实现中确定；首版不加入多模型并行回答或自动路由。

### 4.4 全局后台提示

- 不论当前看论文、稿件还是设置，都能知道后台实验完成、失败或需要处理。
- 提示显示所属任务和运行，点击后才导航；不抢当前焦点、不切走稿件、不自动重发消息。
- 对重复状态去重；状态未知与失败分开，失败提供查看原因的入口。
- 首版只承诺应用打开期间的提示，不预设系统推送或离线通知能力。

所有工作区的变化均来自后台已保存的真实记录/文件与版本：论文入库更新文献列表，实验产物更新运行/结果视图，稿件实际文件保存后编译并更新对应版本的预览。显示下载、解析、运行和构建进度及可恢复失败；重连后可查当前状态，重复事件不产生重复产物，更新不抢焦点或覆盖用户草稿。此链路按 PLAN 第 9 节单独推进，不因原型中出现卡片就认定能力已接入。

## 5. 页面列表与导航关系

这里的“页面”主要是同一工作台里的中央视图或详情标签，不要求每项都有独立网址，也不要求十个入口全部永久占据主导航。项目入口未选任务时不需要伪造会话；设置打开时保留当前任务上下文。

| 页面 | 名称 | 主要目的 | 主要入口 |
| --- | --- | --- | --- |
| P01 | 项目入口 | 创建、查找和重新打开研究项目 | 首次启动、项目切换入口 |
| P02 | 项目概览与任务管理 | 理解项目现状、选择或创建下一项任务 | 打开项目、项目名称、任务导航 |
| P03 | 材料与文献管理 | 检索、导入、筛选和查看材料来源 | 材料入口、会话中的来源链接 |
| P04 | 材料阅读与笔记 | 阅读指定论文/文本并围绕材料讨论 | 材料列表、引用、对象标签 |
| P05 | 研究方案与复现准入 | 编辑/确认方案并查看可执行条件 | 方案入口、Agent 草案或待确认卡片 |
| P06 | 实验管理与运行详情 | 审批提案、查询运行、查看日志和取消 | 实验入口、后台提示、运行链接 |
| P07 | 结果分析与对比 | 阅读指标和图表，理解比较条件与来源 | 结果入口、运行产物、分析链接 |

| P10 | 设置与能力状态 | 配置模型/环境并了解工具可用性 | 全局设置入口、缺配置提示 |

## 6. 每个页面的模块结构

### P01 项目入口

目的：让首次用户有明确起点，让已有用户快速回到最近研究。

| 模块 | 功能需求 | 关键内容/动作 |
| --- | --- | --- |
| 最近项目 | 项目列表和最近打开信息 | 名称、简短描述、最近活动；打开已有项目 |
| 新建项目 | 创建研究项目 | 项目名称必填、描述可选；成功后进入项目概览 |
| 查找与排序 | 项目较多时快速定位 | 按名称查找、按最近活动排序；不预设复杂标签系统 |
| 启动状态 | 告知本地服务是否可用 | 正在连接、连接失败、重试；缺模型配置不阻止查看已有项目 |

主要动作：新建项目、打开项目。不以注册、团队邀请或购买额度作为首版入口。

### P02 项目概览与任务管理

目的：理解当前研究状态并继续工作，不堆砌无关统计图。

| 模块 | 功能需求 | 关键内容/动作 |
| --- | --- | --- |
| 项目摘要 | 展示目标、约束和项目描述 | 查看/编辑基本信息，不把 Agent 推断自动当作已确认目标 |
| 任务列表 | 新建、选择、继续任务 | 标题、目标、状态、最近活动；与左侧任务导航保持一致 |
| 研究资产入口 | 进入已有材料、方案、运行、结果和稿件 | 真实对象摘要或最近产物，点击打开对应中央标签 |
| 待处理事项 | 聚合待确认方案/实验、失败运行、需要核对的稿件 | 每项说明原因及下一动作，避免抽象“风险分数” |
| 继续上次工作 | 恢复当前任务的工作现场 | 标签、对象、阅读位置、布局和草稿；不自动提交消息或重跑实验 |

主要动作：创建/继续任务、查看待办、打开产物。可以从已有实验或稿件接入，不强制先读论文。

### P03 材料与文献管理

目的：集中管理有来源的研究输入，便于阅读与引用。

| 模块 | 功能需求 | 关键内容/动作 |
| --- | --- | --- |
| 检索 | 按论文标题、模型名或问题检索 | 展示真实命中及来源；同名结果供用户核对，不把第一条默认当目标论文 |
| 导入 | 从 DOI、URL、项目可访问文件导入 | 显示处理进度、来源和结果；是否提供本地拖放上传由原型/可用接口确认 |
| 材料列表 | 按类型、关键词和处理状态查找 | 默认当前任务，可切本项目全部；标题、作者/年份、类型、来源、下载/整理状态、关联任务，阅读进度另记；可进入阅读或添加到当前消息 |
| 材料详情 | 核查身份与可用性 | 作者/年份/DOI（可获得时）、来源链接、许可/版本、文件与文本可读性 |
| 引用与关联 | 与讨论和稿件衔接 | 查看来源、添加到对话；参考文献导出及稿件引用入口 |

主要动作：检索、导入、打开材料、添加到对话。跨项目资料不能因标题相同而混用；搜索记录与已导入材料要有可辨区别。

新增框架要求：支持按主题和时间范围收集整理文献；公开全文按识别、解析获取地址、下载校验、保存与自动入库反馈。列表区分仅元数据、获取中、已下载、可读及失败原因；无公开副本、网络/授权或解析失败可重试或导入已有文件。同一论文复用身份记录，附件/版本可区分；方向概览保留集合与证据，并标明元数据/摘要或全文阅读层级。首批来源、工具参数及细化验收留待文献专题讨论，当前 DOI 导入不能视为已获取全文。

### P04 材料阅读与笔记

目的：阅读和讨论同时进行，保留定位与笔记。

| 模块 | 功能需求 | 关键内容/动作 |
| --- | --- | --- |
| 阅读区 | 查看 PDF 或可读文本 | 页码/位置、缩放、可用的文内查找；无可靠全文时如实提示 |
| 来源头部 | 确认当前材料身份 | 标题、来源/版本、打开原链接、下载可访问文件 |
| 材料切换 | 在同项目材料间切换 | 临时展开的列表或已有内容标签，不永久挤占阅读空间 |
| 笔记区 | 记录阅读要点及未核验想法，按需展开 | 论文列表展开时默认收起笔记/元数据，优先保证正文；可编辑笔记、对应材料和位置，与论文原文、Agent 回答区别呈现 |
| 讨论入口 | 将材料或可定位选区加入右侧输入 | 引用卡片显示出处；用户确认发送后才进入本次上下文 |
| 对照区 | 需要时对比两份材料或材料与笔记 | 两侧可独立阅读并保留位置，用户可退出对照 |

PDF 若只能可靠取得整篇/页码，明确只提供该粒度引用；不显示无法兑现的段落选择或 OCR 功能。笔记保存机制是待实施需求，不宣称当前已有独立笔记系统。

### P05 研究方案与复现准入

目的：把讨论中的想法变成用户明确确认、条件可核查的方案。

| 模块 | 功能需求 | 关键内容/动作 |
| --- | --- | --- |
| 方案编辑 | 整理目标、假设、设计、条件、指标与种子 | 草案/已确认/已拒绝及版本；修改后的内容不能继续冒用原确认状态 |
| 预算与资源 | 展示运行次数、时长和环境需求 | 用户可理解的上限；价格未知时明确未知，不用估算冒充精确费用 |
| 材料准入 | 展示是否具备目标实验条件 | 论文身份、官方仓库版本、官方脚本/参数、数据许可/划分、至少两份其他组实际复现依据 |
| 缺失与待核验 | 解释为何尚不能启动目标实验 | 材料充分、材料不足、待核验三类，列出具体缺项与来源 |
| 确认与后续 | 用户审阅并确认或退回 | 确认方案不等于批准训练；之后进入独立的实验提案与批准 |

材料不足时允许补资料或明确做 smoke 调试，但不能把 smoke 当目标复现。没有官方脚本/参数时不静默猜参或独立补实现。

### P06 实验管理与运行详情

目的：知道批准了什么、运行到哪里、结果属于哪一次实验。

| 模块 | 功能需求 | 关键内容/动作 |
| --- | --- | --- |
| 待审批提案 | 显示待批准的精确运行方案 | 目标/smoke、命令/配置、条件、种子、预算、预期产物与对应方案；批准/拒绝 |
| 运行列表 | 按任务、状态定位运行 | 名称、所属任务、类型、状态、起止时间；相同配置的多次运行仍可区分 |
| 运行详情 | 检查执行条件与来源 | 运行标识、快照、代码/数据/环境说明、配置和资源上限 |
| 实时日志 | 阅读运行输出和错误 | 默认显示关键摘要，按需展开详细日志；不让整页被长日志占满 |
| 产物与核验 | 打开指标和原始文件，登记核验说明 | 进程状态与“未核验/部分/已核验”并列；进入结果分析 |
| 运行操作 | 取消排队/运行中的实验，查看失败原因 | 取消请求处理中与已取消分开；失败后新运行需要新的明确提交 |

状态至少区分：排队、运行中、成功退出、失败、已取消、状态未知。未知不显示成功或自动重跑；Agent 空闲不表示训练结束。批准训练、扩大预算和取消实验都要清楚展示作用对象。

### P07 结果分析与对比

目的：展示真实测量值及比较条件，支持负结果。

| 模块 | 功能需求 | 关键内容/动作 |
| --- | --- | --- |
| 运行选择 | 选择用于分析的运行 | 类型、状态、核验状态、版本和所属任务；保留原始来源 |
| 指标表 | 查看数值、单位和指标方向 | 每个值可定位到运行及原始文件/位置，缺失值不显示为零 |
| 条件对照 | 判断是否能直接比较 | 数据版本/划分、预处理、实验任务等差异，以及种子/预算限制 |
| 图表区 | 在条件允许时呈现图表 | 与表格来源一致；不可比时说明原因，不做误导排名 |
| 分析报告 | 查看带来源的解释与限制 | 负结果、失败、partial、smoke 均保留明确标识 |
| 结果版本与联动 | 查看历史版本、明确替换结果、加入消息或用于稿件 | 新增不等于撤回旧结果；替换被引用版本时提示相关稿件需核对 |

没有目标运行或尚未核验时，不出现“复现成功”“方法提升”等无依据结论。失败运行可以形成忠实分析，不必伪造成成功。

目的：让用户围绕可编辑、可编译、可回查的稿件持续工作。

| 模块 | 功能需求 | 关键内容/动作 |
| --- | --- | --- |

| 编辑区 | 编辑文本或 LaTeX 源码 | 输入草稿保护、保存、版本冲突提示；编辑器视觉沿用原稿，源码/PDF/对照可切，避免过窄折行 |

| 结果与参考材料 | 查看引用来源、插入/同步已选择的结果 | 表格/图表关联结果版本；缺来源或结果替换时提示核对 |

Agent 生成或建议修改与用户已保存正式稿件应可区分；新界面不自动赋予 Agent 任意写稿权限。首版以英文基础 article 和中文讨论为范围，不承诺所有期刊格式。

### P09 审稿意见与修订

目的：把意见、回应、修改和补充证据对应起来，仍在同项目中继续研究。

| 模块 | 功能需求 | 关键内容/动作 |
| --- | --- | --- |
| 意见输入 | 导入或粘贴审稿意见 | 保留原文和来源说明，可按条目整理 |
| 修订清单 | 明确每条意见的处理进度 | 待处理、处理中、待核对、已处理；“已处理”须有回应或产物依据 |
| 对照工作区 | 查看当前选中意见与相关稿件/修改 | 左栏选意见，中央不重复常驻完整清单；对应段落、修改前后版本可按空间切单内容/对照，不另开独立投稿平台 |

修订清单与逐条回应是本次原型要表达的目标模块，其具体数据组织待实施设计；不能把现有“导入意见为任务”当作完整修订管理已实现。

| 模块 | 功能需求 | 关键内容/动作 |

| 模型与凭据 | 配置 DeepSeek 及 Pi 实际支持的模型选项、凭据和新任务默认模型 | Key 输入掩码、已配置/未配置、保存/清除；不回显完整密钥，不虚构厂商支持；返回对话框即可选择当前任务模型，规则见 MS01–MS07 |

## 7. 共通交互规则

| 规则 | 需求 | 需要体现的反馈 |
| --- | --- | --- |
| I01 | 中央内容切换不改变当前任务/会话；切换任务恢复其工作现场 | 当前项目、任务、标签均清晰可辨；无任务时不可误发 |
| I02 | 显式选择本次消息引用，发送前可移除，发送后可回查 | 引用显示标题、位置/版本及失效提示；打开不等于自动送给模型 |
| I03 | 固定/临时标签、重复打开定位、对照与辅助区可恢复 | 关闭标签不删除业务文件；Agent 不随意关闭/重排固定内容 |
| I04 | 发送、保存、确认、批准、构建等异步操作防重复 | 操作中明确反馈；不因超时/重连自动创建第二个任务、消息或实验 |
| I05 | 停止回答、取消实验、关闭标签、删除数据分别表达 | 显示实际作用对象和影响，不用一个模糊“停止”代替全部动作 |
| I06 | 草稿保护覆盖切任务、关标签、刷新及服务端版本变化 | 保存/放弃/取消，自动恢复本地草稿，冲突提示；不静默覆盖正式稿件 |
| I07 | 后台提示可见但不抢焦点 | 显示任务/运行和查看入口；重复状态去重，用户点击才跳转 |
| I08 | 错误可理解、可恢复，局部失败不抹掉整页内容 | 说明失败对象、原因和重试/配置/补材料路径；保留输入和已加载内容 |
| I09 | 结果可信度与执行状态分别呈现 | smoke/target、核验状态、不可比、未知、负结果均不能被统一绿色成功替代 |
| I10 | 键盘和触控均可使用关键操作 | 中文输入法、Enter/Shift+Enter、焦点顺序、可见焦点和带文字的状态；操作不依赖悬停 |
| I11 | 对话框内模型切换遵守 MS01–MS07 | 当前生效模型、切换中及失败清晰；下一条消息生效、按任务恢复，不静默换模型或重放消息 |

实验批准须让用户能看到将执行的精确配置与预算；新目标、扩大预算、覆盖正式稿件保留明确确认。导入论文、网页或审稿意见不意味着其中的指令获得宿主权限。

## 8. 空状态、加载状态与异常状态

每个状态都应包含：当前发生了什么、影响哪个对象、可以做什么。空数据不展示伪造论文、数值、图表或成功记录；原型示例数据须明确为示例。

### 8.1 各页面状态清单

| 视图 | 空状态与下一步 | 加载/处理中 | 失败或不可用时 |
| --- | --- | --- | --- |
| 项目入口（P01） | 无项目：说明项目用途，提供新建入口；搜索无结果：清空筛选 | 正在连接服务/加载项目列表，保留新建入口的合理反馈 | 服务不可达：重试与启动说明，不能显示“暂无项目”掩盖请求失败 |
| 项目概览（P02） | 无任务：创建任务或导入已有材料；无产物：说明可从哪一步开始 | 各类资产和任务分区加载，不用全页转圈阻断已有内容 | 局部资产失败可独立重试，旧概览标明可能过期 |
| 材料管理（P03） | 无材料：检索/导入；无命中：修改查询或换导入方式 | 区分检索中、下载/导入中、文本提取中 | 来源不可达、文件不支持、同名歧义、重复材料提供核对/重试入口 |
| 阅读与笔记（P04） | 未选材料：选择材料；无笔记：开始记录；无可读文本：换可读副本 | 文档与页内容加载，显示材料名/位置，不清空笔记草稿 | 文件不存在、PDF 解析失败/扫描件无文本：解释限制，保留来源和下载入口（若可用） |
| 方案与准入（P05） | 无方案：手动创建或让 Agent 整理草案 | 保存/核对证据/提交确认中，禁止重复决策 | 条件不全、材料不足、方案已变化或预算冲突：列出缺项，不显示已确认 |
| 实验（P06） | 无提案/运行：先确认方案并生成提案；无日志：尚未启动 | 排队、启动、运行、取消处理中有不同文案；无真实进度时不编百分比 | 缺环境、超预算、失败、取消未确认、unknown 提供查看原因和核对入口 |
| 结果（P07） | 无可用指标：查看运行/产物并导入；未核验：提示核验 | 导入、计算对比、生成图表/报告时保留已有结果版本 | 旧/缺失/非数值指标、条件不可比：明确标记，不补零、不强行绘制排名 |
| 稿件（P08） | 无稿件：从基础模板开始；未编译：显示首次构建入口 | 文件加载、保存、编译、导出分别显示，不假定成功 | 编译错误、缺图/引用、TeX 不可用、旧 PDF、版本冲突：定位问题并保留源码 |
| 审稿修订（P09） | 无意见：粘贴/导入；尚无修改：关联稿件或建立修订任务 | 意见整理、保存回应、加载版本差异时有局部反馈 | 不能解析意见、关联版本丢失、补实验不具备条件：支持手动整理和补资料 |
| 设置（P10） | 未配置模型/环境：说明分别影响哪些能力 | 保存、能力探测中明确显示对象；未实际探测不显示通过 | Key 无效、网络错误、路径不存在/依赖缺失：反馈到对应设置，不回显密钥 |

### 8.2 会话与全局状态

- **首次会话**：显示当前任务目标、可引用的已有材料和简短行动建议，不生成假的助手历史。
- **正在回答**：流式内容与可展开的工具进度；允许停止回答。长实验等待独立显示，不让模型持续空转。
- **待用户确认**：显示决策摘要与对应方案/实验；可批准、拒绝或查看详情，不能只显示不可操作的“待审批”。
- **事件流断连/重连**：保留已有记录与输入，显示连接状态；重连不重复发送消息，服务不可达与模型调用失败分开。
- **未配置/认证失败**：指出需要配置的模型/环境，已有材料和产物仍可查看，不生成假回答。
- **模型选择与切换**：空列表去配置；加载时保留当前模型；切换中防发送，失败保留原选择与输入；回答期间禁用切换；调用失败不自动换模型。模型/工具能力不兼容时解释限制并让用户选择，不能静默丢失上下文。
- **停止/取消/未知**：分别显示回答已停止、取消请求处理中、实验已取消、运行状态未知；未知不自动重跑。
- **本地恢复异常**：损坏缓存可安全降级；存储不可用/配额不足时保留内存草稿并提示，不能宣称草稿已经保存。

## 9. 移动端、窄屏与可访问性

桌面是主要使用场景，移动端优先保证阅读、对话、查看状态和必要确认可用。以下是响应式交互要求，不承诺手机可直接连接仅监听本机回环地址的服务，也不把远程部署/鉴权加入本次范围。

| 布局环境 | 布局需求 | 关键功能与状态保留 |
| --- | --- | --- |
| 宽屏桌面 | 导航、中央工作区、右侧会话并存；主要区域可调宽 | 对照、编辑/PDF、日志辅助区可组合，阅读和会话各自滚动 |
| 窄桌面/平板 | 优先折叠导航，精简辅助区，避免多栏等宽挤压 | 会话保持可访问；对照不足时支持单侧切换，记住另一侧位置 |
| 手机窄屏 | 显式切换“工作区/对话”，导航用抽屉，复杂辅助区用独立展开层 | 当前任务、未读/运行状态、输入草稿与阅读位置保留，不因切换创建新任务 |

- 表格保留运行名称/关键标识，必要时横向查看或逐条展开，不能靠把文字缩到难以阅读来塞下所有列。
- PDF/图表可缩放，长标题/路径可换行或打开完整信息；复杂 LaTeX 编辑以桌面为主，手机不要求复制完整多栏编辑器。
- 输入区不被软键盘遮挡；附件、发送、停止、确认、取消等目标具备足够触控面积。
- 拖动调整宽度不能成为访问内容的唯一方法；键盘也能切标签、展开面板和完成确认。
- 状态同时使用文字和可辨样式，不能只靠红绿颜色；图标按钮有标签，焦点可见，错误与加载有可读提示。
- 原型至少检查 1440、1024、390px 三档可用性，实际断点根据内容和原型确定，不预先锁死布局比例。

## 10. 视觉风格关键词与留白项

关键词：**清晰、克制、专注阅读、层级明确、状态可信、信息密度可调、长时间使用舒适。**

视觉以 Stitch 原稿为准，不采用最后一轮改乱后的变体。沿用浅色背景、细边框、克制的蓝色点缀、字体层级和按钮/图标语言；不要求延续旧前端或旧 Demo 的视觉，也不重新推翻已经认可的风格。原稿资源和排除清单见 PLAN 第 8.7 节。

右侧会话、项目/任务/产物边界和草稿保护保持既定方向。具体宽度、留白、辅助区收纳和编辑器排布在实现中按真实内容修正；必须保证阅读/编辑可用，不照搬正文过窄、浮层溢出和表格截断等已知问题。

## 11. 实现与视觉核对需要覆盖什么

以下是实现时需要覆盖的画面与状态，不是继续让 Stitch 改稿的待办；直接读取原稿，按 PLAN 的 UI01–UI09 修正，不必先把每个页面画成独立路由。

1. 桌面主界面：项目/任务导航、中央对象标签、右侧会话、输入引用区与后台提示；模型选择器展开、空列表、切换中/失败、回答期间禁用状态。
2. 阅读状态：一篇真实样例论文、可收起的材料/笔记、发送引用；对照状态可以单独补图。
3. 实验与分析状态：待批准提案、运行中、失败/未知、指标表与条件差异、不可比结果。
4. 写作状态：文件/章节、编辑/PDF 对照、未保存标记、编译失败及版本冲突。
5. 修订状态：意见、对应修改、回应及补实验入口，沿用同项目和右侧会话。
6. 通用状态：无项目/无任务/无材料、加载、断线、配置缺失、关闭未保存内容。
7. 窄屏状态：导航折叠、工作区/对话切换、模型选择、软键盘打开时的输入与确认操作。

实现核对：是否遗漏模块、实际空间是否足够、关键操作在哪里、失败后如何继续。原稿与已登记修正冲突时按 PLAN 第 8.7 节执行；不为了复刻外观静默删除功能，也不将静态原型当作真实功能通过证据。

### 12.2 实施设计需落地的细节

- 主导航、项目列表、任务列表的具体排布；哪些入口常驻，哪些从对象或菜单进入。

- 临时/固定标签、对照方式、材料/日志/笔记辅助区的具体操作。
- PDF 阅读组件的实际选区能力与笔记持久化方式；不先承诺做不到的定位粒度。
- 材料导入首批是否增加浏览器上传，及对应大小/类型限制；项目路径输入不能冒充手机文件上传。
- 方案修改、Agent 稿件建议、修订条目的审阅与保存方式，现有权限不足时如何明确等待确认。
- 保存反馈、草稿恢复、版本冲突、失败提示和预算批准的文字及呈现方式。
- 整体视觉沿用 Stitch 原稿；具体字号、密度和触控布局在 W00–W02 用实际内容核对，不以等待新原型为前置。
