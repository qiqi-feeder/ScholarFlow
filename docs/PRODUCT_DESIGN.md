# ScholarFlow 产品设计文档（MVP）

## 1. 产品概述

ScholarFlow 是一个面向科研全流程的智能体工作台，基于 Pi Agent Runtime 构建。产品以 **Research Project** 为核心，帮助研究者持续管理论文、笔记、证据、代码和实验结果，并通过 Agent 将不同科研环节连接起来。

ScholarFlow 不强调固定流程。用户可以从文献搜索、论文阅读、研究笔记或实验中的任意环节进入，并将已有材料和新生成的产物在项目内持续流转。

MVP 首先服务计算机、人工智能和数据科学等计算型科研场景，验证用户是否愿意在一个长期项目空间中完成“文献—证据—实验”的最小闭环。

## 2. 产品目标

- 建立以 Research Project 为边界的长期科研上下文。
- 让 Agent 的输出成为可复用、可追溯的项目资产，而不只停留在聊天记录中。
- 提供带原文位置的论文阅读与证据整理能力。
- 支持轻量、受控且可追溯的计算实验。
- 允许用户独立使用任一模块，同时支持跨模块协作。

## 3. 产品形态

MVP 采用 **桌面端优先、本地优先** 的产品形态，建议使用 Electron + React 实现：

- Electron 提供本地文件、进程、窗口和系统能力。
- React 构建可复用的工作台界面。
- Pi Agent Runtime 在主进程或独立本地服务中运行。
- SQLite 保存项目、资产、引用、会话和实验元数据。
- PDF、代码、数据与实验结果保存在用户指定的本地目录。

后续可以提供 Web Companion，用于跨设备阅读、轻量编辑、同步和分享，但首版不承担云端实验和完整协作能力。

## 4. 核心概念

| 概念 | 定义 |
| --- | --- |
| Research Project | 最高级别的数据、权限和 Agent 上下文边界 |
| Project View | 文献、阅读、笔记、证据、实验等功能视图 |
| Artifact | 论文、笔记、代码、数据集、图表或实验结果 |
| Agent Profile | 面向某类任务的角色、工具权限和上下文策略，如 Reader、Writer、Reviewer、Experimenter |
| Skill | 可按任务加载的专业方法与执行规范，如 Nature Writing |
| Agent Session | 围绕一个具体科研任务展开的对话与执行历史 |
| Context Handoff | 在不同 Session 之间传递的结构化目标、假设、约束与资产引用 |
| Experiment Run | 一次可追溯的实验执行记录 |

一个 Project 可以包含多个 Agent Session。Session 可以共享项目资产，但保持各自的任务上下文和历史记录。

## 5. 信息架构与界面布局

整体采用简化的 VS Code 式工作台布局，但降低信息密度：

- **顶部栏**：当前项目、项目切换、全局搜索和快捷命令。
- **左侧活动栏**：项目概览、文献、笔记、证据、实验和搜索。
- **左侧边栏**：展示当前视图下的论文、文件、笔记或实验记录。
- **中央编辑区**：通过标签页打开 PDF、Markdown、表格、代码和实验结果，MVP 支持最多左右两栏。
- **右侧 Agent 面板**：展示对话、当前上下文、任务步骤、工具调用和生成产物。
- **底部面板**：按需展示实验日志、终端、错误和后台任务。

同一窗口默认只打开一个 Project。切换项目时，资源树、标签页、Agent Session、实验记录和布局状态整体切换。跨项目引用必须由用户显式复制、移动或关联。

## 6. MVP 主要功能

### 6.1 项目管理

- 创建、打开和归档 Research Project。
- 设置研究目标和项目说明。
- 导入本地论文、笔记、代码和数据。
- 保存每个项目独立的界面状态与 Agent Session。

### 6.2 文献搜索与管理

- 通过 OpenAlex、Crossref 或 arXiv 搜索论文。
- 导入 PDF、DOI 或 arXiv 链接。
- 保存标题、作者、年份、摘要和标识符等元数据。
- 文献去重、项目收藏和 BibTeX 导出。

### 6.3 论文阅读

- PDF 阅读、搜索和基础批注。
- 基于论文原文进行问答。
- 提取研究问题、方法、数据集、指标、结果和局限。
- 回答必须尽可能提供论文及页码定位，并区分原文事实与 Agent 推断。

### 6.4 笔记与证据

- 创建和编辑 Markdown 研究笔记。
- 将原文片段或 Agent 回答保存为证据卡片。
- 记录证据来源、页码、解释和标签。
- 根据多篇论文生成文献对比表、方法矩阵和初步研究空白。

### 6.5 实验工作区 Lite

- 关联本地代码目录和小型数据集。
- 允许 Agent 在授权范围内读取、编辑代码并运行命令。
- 保存输入、参数、代码版本、命令、日志、退出状态和输出文件。
- 将实验图表和结论保存回项目笔记或证据库。
- 支持根据历史配置重新运行实验。

### 6.6 项目 Agent

- 理解当前 Project、活动视图和用户选中的 Artifact。
- 展示明确的上下文范围，例如当前 PDF、所选论文或当前实验。
- 调用文献、笔记、文件和实验工具完成跨模块任务。
- 流式展示计划、工具调用、进度、文件变更和最终产物。
- 对写文件、执行命令等高风险操作提供可配置的确认机制。

### 6.7 导出

- 导出 Markdown 笔记。
- 导出 BibTeX 文献数据。
- 导出 CSV 格式的证据表或文献对比表。

## 7. Pi Agent Runtime 的职责

Pi Agent Runtime 作为智能执行层，主要负责：

- 创建、恢复和分支 Agent Session。
- 维护单次科研任务的对话与执行状态。
- 根据用户目标规划步骤并选择工具。
- 调用文献检索、原文查询、笔记保存和实验运行等自定义工具。
- 在项目目录范围内读取、搜索和编辑文件。
- 将模型输出和工具事件流式发送给工作台界面。
- 通过 Skills 沉淀论文阅读、证据整理和实验分析等科研方法。
- 为不同任务配置模型、工具与权限范围。

ScholarFlow 自身负责以下业务能力：

- Project、Artifact、Citation 和 Experiment Run 数据模型。
- PDF 解析、全文索引、页码映射和引用校验。
- 文献接口、元数据去重和文件存储。
- 操作系统级沙箱、资源限制与危险操作拦截。
- UI 状态、权限、同步、协作和后续计费能力。

Pi Session 不能作为 ScholarFlow 的业务数据库；所有需要查询、关联、导出和长期保存的数据都应进入 ScholarFlow 的领域数据层。

### 7.1 Agent 动态组合

用户在同一个 Agent 面板中连续对话，但一个 UI Conversation 可以包含多个任务级 Pi Session。工作区只提供默认路由，不与 Agent 一一绑定：阅读任务默认使用 Reader，论文撰写默认使用 Writer，独立审查使用 Reviewer，代码和实验任务使用 Experimenter。

一次任务由以下部分动态组合：

- ScholarFlow 全局安全与科研诚信规则。
- 当前 Research Project 的目标与项目规范。
- Agent Profile 定义的角色、上下文策略和工具权限。
- 按任务加载的 Skills，例如 Nature Writing 或 Citation Audit。
- 当前选中的论文、笔记、证据、代码或实验结果。

相同 Profile、权限和任务范围内的连续消息可以复用 Session；Profile、工具权限或任务目标明显变化时，应创建新的 Session。用户显式选择优先于自动路由，MVP 提供 Auto、Writer、Reviewer、Experimenter 等模式。

论文写作与排版需要分开处理：Skill 负责结构、论证、语言和期刊规范，LaTeX、Word、引用校验与编译等确定性工作由专用工具完成。

### 7.2 上下文隔离与交接

上下文分为三层：

| 类型 | 范围 | 主要内容 |
| --- | --- | --- |
| Project Context | 项目内共享 | 项目目标、已确认事实、Artifact、证据和实验结果 |
| Session Context | 当前任务私有 | 对话消息、工具调用、临时计划和调试过程 |
| Context Handoff | Session 间显式传递 | 目标、假设、决定、约束、待解决问题和 Artifact 引用 |

用户仅切换工作区时不创建 Session；当用户在新工作区发起任务时，系统再决定复用、分支或创建新的 Session。Reader、Writer 与 Experimenter 之间切换时，默认不复制完整聊天记录，而是生成可检查的 Context Handoff，只传递与新任务相关的内容。

上下文切换支持三种模式：

- **Clean**：新任务与前文无关，仅加载 Project Context 和当前选择。
- **Handoff**：将前序讨论中的目标、假设、约束和资产引用传递给新 Session，作为默认模式。
- **Fork**：任务本质未变化，只需延续现有推理或增加相近能力时，从原 Session 分支。

Session 完成后，应将稳定结论写回 Evidence、Note、Experiment Run 或其他 Project Artifact。后续 Session 优先读取这些可追溯资产，而不是依赖完整聊天历史；上下文不足时，可以通过受限工具按需查询同一 Project 的历史内容。

参考：[Pi SDK 官方文档](https://pi.dev/docs/latest/sdk)

## 8. 典型使用场景

### 文献研究

用户创建项目并输入研究问题，搜索和保存若干论文。Agent 阅读用户选中的论文，提取方法、数据集和结果，生成带来源定位的证据表，并保存为项目笔记。

### 论文复现

用户在阅读论文时要求复现实验。Agent 提取论文中的实验设置，检查现有代码，生成或修改实验配置，在授权后执行命令，并将日志、结果和与原论文的差异保存为 Experiment Run。

### 已有项目接入

用户直接打开包含代码、PDF 和笔记的本地目录。ScholarFlow 对材料建立索引，但不要求用户从文献搜索开始。Agent 可以基于现有资产继续阅读、整理或实验。

## 9. MVP 暂不包含

- 自动撰写完整论文。
- 多人实时协作和复杂权限体系。
- 完整替代 Zotero、Mendeley 或专业 IDE。
- 多 Agent 编排界面。
- 大规模 GPU 集群与云端任务调度。
- 通用湿实验管理。
- 自动投稿、期刊推荐和科研社交功能。
- 面向所有学科的深度定制。

## 10. MVP 成功标准

- 用户能在 15 分钟内创建项目、保存论文并生成第一条带出处的证据。
- 论文问答能够稳定定位到正确论文和页码。
- 用户会将 Agent 输出保存为笔记、证据或实验产物。
- 用户能够完成至少一次可追溯、可重新运行的轻量实验。
- 用户会在同一项目中组合使用文献、笔记和实验中的至少两个模块。
- 用户在一周内重新打开并继续使用同一个 Research Project。

## 11. 后续方向

在 MVP 验证后，可以逐步增加云端同步、项目分享、团队协作、更多文献源、引用网络、LaTeX 写作、多 Agent 协作、远程实验环境和机构级知识库。
