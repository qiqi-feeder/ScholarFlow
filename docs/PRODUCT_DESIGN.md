## 1. 产品概述

ScholarFlow 是基于 Pi Agent Runtime 的科研工作台，以 **Research Project** 为核心，持续管理论文、双语阅读产物、笔记、证据、实验数据与论文稿件。

采用 **可自托管 Server＋Web 工作台**：在自己的电脑、实验室机器或远程服务器启动 ScholarFlow Server，通过浏览器连接；Pi 和任务工具在 Server 侧执行。首版面向计算机、AI 和数据科学研究者，不是只有聊天框的网页，也不是首版即面向公众的多租户 SaaS。

工作区提供不同材料的组织方式，不要求固定科研流水线。用户可从阅读、写作或已有实验数据进入，在同一项目内复用产物。

## 2. 产品目标

- 让专业 Skill 真正进入执行流程，不只是更换提示词名称。
- 输出落成可打开、追溯、编辑和导出的项目文件。
- 打通“选论文＋选 Skill → 中英对照阅读 → 证据/笔记 → 写作与排版”主线。
- 支持受控、可记录的计算实验，不把浏览器当执行机器。
- 页面关闭后后台继续，重连查看同一任务，清楚说明崩溃恢复边界。

## 3. 产品形态

### 3.1 首版：Server＋Web

浏览器负责界面、上下文选择、编辑预览和提交请求；ScholarFlow Server 负责业务数据、鉴权、文件、任务和 Pi 接入；Pi 负责模型与工具循环。Pi SDK 不是可直接暴露的 ScholarFlow HTTP Server。

| 部署方式 | 执行与主数据的位置 | 使用方式 |
| --- | --- | --- |
| 本机自托管 | 自己电脑上的 Server | 浏览器打开本机地址 |
| 实验室/远程自托管 | 指定机器上的 Server | 可信私网/VPN或正确配置的 HTTPS |
| 后续 Electron | 内置本机 Server 或连接远程 Server | 复用 Web 工作台，加桌面集成 |

首版单用户，不做复杂团队权限；远程模式必须鉴权，不能用“内网”代替安全措施。本机也须防跨站请求和非预期 Origin 访问。

### 3.2 数据归属与连接行为

主数据默认由 Server 所在机器管理，写入可配置的 `dataRoot`：论文/PDF、解析文本、图片、双语产物、实验代码/数据/参数/日志/结果、稿件/模板/排版输出、会话与配置。浏览器缓存不是业务数据库。

- 上传在 Server 创建副本，不删除客户端原文件；下载产生客户端副本。
- 浏览器不能直接打开远程 Server 看不到的本地路径。已有目录接入指 Server 侧显式授权的目录。
- 后续可接挂载盘或对象存储；主数据仍由 Server 管理，未必在系统盘。
- 自托管不等于绝不出网：外部模型可能接收相关原文，检索接口也可能出网。显示发送范围并配置网络策略；本地模型是选项，首版不要求 GPU。
- 关闭页面/断线不取消已提交任务，重连读取同一 Run；Server 重启保留记录与已确认产物，但中断中的模型调用不承诺无缝续跑，标为 `interrupted`，用户决定重试。

### 3.3 Electron 的位置

Electron 是后续客户端，不是新的 Agent 引擎。Web 先行减少打包与跨平台成本；组件和 HTTP 协议可复用，但本地服务生命周期、文件对话框、更新、系统权限与离线能力仍需单独实现和验收。

## 4. 核心概念

| 概念 | 定义 |
| --- | --- |
| Research Project | 领域数据、上下文和访问控制边界 |
| Workspace / Project View | 功能视图，不等于独立 Agent |
| Artifact | 带类型、版本、来源与真实文件的项目资产 |
| Agent Profile | 角色、上下文策略和宿主工具权限，如 Reader、Writer、Reviewer、Experimenter |
| Skill Package | `SKILL.md` 与引用、脚本、模板、共享资源组成的专业方法包 |
| UI Conversation / Agent Session | 用户对话 / Pi 执行历史；一段对话可关联多个任务级 Session |
| Context Handoff | 显式交接的目标、假设、约束、问题与带版本资产引用 |
| Agent Run | Server 管理的任务，记录输入、Skill 快照、模型、事件、状态与产物 |
| Experiment Run | 额外保存代码、环境、配置和输入输出 hash 的计算实验记录 |
| Manuscript / Build | 稿件源文件与一次确定性排版构建，分别版本化 |

Session 共享项目资产，但不自动共享全部聊天历史；清理 Session 不删除业务文件。

## 5. 信息架构与界面布局

延续已确认的明亮 IDE 风格：稳定侧栏、标签页、分栏与可收起 Agent 面板；优化信息层级、排版和密度，不仅换配色。

- 顶部：Server 连接/身份、项目切换、全局搜索、命令入口。
- 活动栏：概览、文献、阅读、笔记、证据、**写作与排版**、实验。
- 左侧：当前资源树、列表、过滤与导入。
- 中央：PDF、双语 Markdown、证据表、稿件与 PDF 预览；最多两栏起步。
- 右侧 Agent：上下文附件、Profile、Skill 选择器、输出目标、工具事件、审批、产物链接。
- 底部：后台任务、编译/实验日志与错误，不默认提供无限制宿主终端。

覆盖加载、空数据、断线、失败、无权限、草稿与待审批状态。当前 `demo/workspace-light.html` 只有六个 Mock 功能页，尚缺写作与排版；旧 Demo 和第一版设计继续保留，后续真实应用在新目录实现。

## 6. MVP 主要功能

### 6.1 项目管理与 Server 连接

创建、打开、归档项目，设置目标，上传论文/笔记/实验材料，保存布局和任务。显示连接地址、Server 版本、存储位置与能力。既有目录必须显式授权，不自动扫描整台机器。

### 6.2 文献搜索与管理

第一条闭环优先 PDF 上传、元数据编辑、去重与 BibTeX 导出。在线检索作为增量，先接一个文献源，验证标识符、限流、失败与合法全文获取，再扩展其他来源。DOI 可用不代表全文可合法下载。

### 6.3 论文阅读：真实 Skill 闭环

用户选择真实 `nature-reader`，绑定论文并要求“生成中英对照阅读版”；执行其流程，产出 `paper.md`、`source_map.json`、`translation_notes.md` 与必要的 `assets/`，再由通用阅读器展示，不为每个 Skill 重写前端。

首个验收限定合法、可选择文本的 PDF。扫描/OCR、复杂公式、缺图或不完整全文需提示限制并标记草稿，不能静默退化成摘要再宣布“全文完成”。问答和选段翻译按对应任务处理，不强制每次重建全文。

上游是社区 [nature-reader](https://github.com/Yuan1z0825/nature-skills/blob/main/skills/nature-reader/SKILL.md)，不表示 Nature 期刊官方背书。按路由加载核心/来源资源，遵循[输出契约](https://github.com/Yuan1z0825/nature-skills/blob/main/skills/nature-reader/static/core/output-contract.md)。实施时固定仓库 commit 并核验依赖，不依赖变化中的 `main`。

### 6.4 笔记与证据

编辑 Markdown，保存原文片段或确认后的回答为证据卡；绑定论文版本、页码/块 ID、解释与标签。区分原文事实、用户决定和模型推断。对比表保留各项来源，非法引用不得冒充已核验。

### 6.5 实验工作区 Lite

先导入已有结果/配置，再支持用户批准的轻量 CPU 实验，在隔离执行器内运行。保存代码/镜像版本、参数、种子、输入输出 hash、日志、退出状态与耗时；图表可关联笔记/稿件。固定样例可验证重跑，不承诺所有科研数值绝对相同。

实验在 Server 或其配置的隔离执行环境执行，不默认在访问网页的电脑执行；GPU 集群不是前提。

### 6.6 项目 Agent 与 Skill 接入

配置分层：**用户 Skill 库 → 项目启用 Skill → 工作区推荐/默认 → 对话显式选择**。同一 Skill 可出现在多个工作区，不等于复制多个固定 Agent。

对话区提供 Skill 搜索/选择器及等价命令入口。发送前显示来源版本、输入资产、输出目标、缺失能力与权限；执行后展示已加载资源、工具事件、审批、产物和校验。显式选择优先于自动路由，不能悄悄替换。

必须加载完整 `SKILL.md`，按指令读取必要引用、模板和共享资源；仅注入名字不算接入。Skill 不能扩大宿主工具/文件/网络权限，不能自动安装任意依赖或执行未审查扩展。

目标是可发现、可选、可观察执行、可验证产物的同类体验，不保证不同产品/模型结果完全相同。通用指令包与宿主专有 hooks、子代理、命令和 MCP 分别评估；安装报告列出缺失依赖及可用/部分支持/阻断状态。[Pi Skills 官方文档](https://pi.dev/docs/latest/skills)

### 6.7 写作与排版、导出

正式工作区包含稿件树、结构/正文编辑、引用/图表、版本差异、模板、PDF 预览、编译日志与导出。

写作 Skill 负责论证、结构、语言与风格；确定性工具负责文件保存、引用核验和构建。Agent 默认提出修改草案，确认后创建新版本；冲突展示 diff，不覆盖用户修改。编译失败保留上一份成功 PDF，显示本次失败日志。

基于计算型科研定位，**建议先 LaTeX＋PDF，后 DOCX**；这是推荐而非已确认需求，若首批用户主要用 Word，应在实施前调整决策和样例。MVP 导出 Markdown、BibTeX、CSV、稿件源文件和已验证 PDF。

## 7. Pi Agent Runtime 的职责

Pi 在 Server Worker 内通过 SDK 接入，负责模型/工具循环、Session、Skill 执行与事件订阅。ScholarFlow 负责领域数据、鉴权、任务持久化、PDF 解析、来源校验、存储、工具策略、操作系统级隔离、审批和 UI。

Pi Session 不能作为业务数据库；Pi 原始事件不能替代稳定业务协议，网络重连与后台任务也不是浏览器/SDK 自动完成的。[Pi SDK 官方文档](https://pi.dev/docs/latest/sdk)

### 7.1 Agent 动态组合

任务组合：宿主安全/科研诚信规则、项目目标、Agent Profile、显式选择或确认推荐的 Skill、输入资产与输出目标。

同一任务/权限/Skill 快照可复用 Session；目标、Profile、Skill 或权限实质改变时新建任务级 Session。切工作区不自动创建 Agent。专业规范在批准范围内执行，宿主权限始终优先。

### 7.2 上下文隔离与交接

| 上下文 | 范围 | 内容 |
| --- | --- | --- |
| Project Context | 项目共享 | 目标、确认事实、资产、证据与结果 |
| Session Context | 任务私有 | 消息、工具调用、临时计划与调试 |
| Context Handoff | 显式跨任务 | 目标、假设、约束、决定、问题与带版本引用 |

- **Clean**：只接收项目规范与当前选择。
- **Handoff**：展示可检查的结构化交接，不复制完整聊天，作为跨角色默认。
- **Fork**：任务本质未变时分支 Session，权限仍需验证。

结论写回 Artifact/Evidence/Note/Run；跨项目复制/关联显式授权。第一条闭环先实现 Clean 与可见的基础 Handoff，Fork 后续实现，不阻塞阅读 MVP。

## 8. 典型使用场景

### 双语阅读

连接 Server，上传合法 PDF，选 `nature-reader` 并确认输入/输出。加载 Skill 后执行，关页仍继续，重开查看同一 Run。完成后点双语正文出处定位 PDF 页/块，缺失内容可见。

### 证据到稿件

选择证据/图表，用写作 Skill 提出章节草案，核验引用并确认保存；选择模板构建 PDF，查看错误或下载版本化源文件与成品。

### 实验接入

上传结果表/配置或授权 Server 侧目录；需要计算时批准代码、输入和环境，隔离运行并记录。前端设计比较的 Git worktree 实验不等于产品科研 Skill 工作流。

## 9. MVP 暂不包含

- 公众多租户 SaaS、收费、多人实时协作与复杂组织权限。
- 无审查自动完成整篇投稿论文、自动投稿和期刊推荐。
- 任意宿主 shell/文件访问、Skill 自动提权、未审查扩展执行。
- GPU 集群、分布式实验调度与通用湿实验管理。
- 所有来源/OCR/模板开箱即用，所有宿主 Skill 专有机制完全兼容。
- 首版 Electron、离线同步、跨 Server 自动迁移。
- 完整替代 Zotero/专业 IDE，面向所有学科深度定制。

## 10. MVP 成功标准

验收保存证据包；样例、阈值和失败测试见[实现路线](IMPLEMENTATION_ROADMAP.md)。文档/Mock 测试不代表真实功能通过。

| 层级 | 标准 | 节点 |
| --- | --- | --- |
| 阅读技术 MVP | 真 Server 上传、真 Pi＋完整 Skill 资源执行、双语文件/图表/公式/来源校验、UI 可打开 | M1–M5 |
| 后台可靠性 | 断开不取消、重连不重复发模型请求、中断明确标记、审批与权限负例通过 | M3–M5 |
| 科研工作台 MVP | 证据到稿件/真实 PDF 构建，一次可记录重跑的隔离 CPU 实验 | M6–M7 |
| 可交付自托管 MVP | 跨机器浏览器连接，鉴权/隔离、备份恢复和部署可重复验证 | M8 |

试用另行衡量：至少 3 位目标用户，至少 2 位在 15 分钟内产生首条带出处证据，记录失败原因；至少 2 位一周后继续同一项目，使用至少两个模块。独立记录模型耗时，不靠预置结果冒充首任务完成。

## 11. 后续方向

按需求增加 DOCX、OCR、文献源、模板、Fork、Electron、团队权限、PostgreSQL/多 Worker、对象存储和远程执行环境。扩展重新定义迁移与安全验收，不假设 Web 加壳即可获得全部桌面/协作能力。
